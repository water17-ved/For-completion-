# JEE Battle Royale Tracker + AI Coach

A single-page JEE progress tracker (chapter checklists, chapter tests, mocks, revision, study hours, streaks)
with a built-in **AI Coach** tab. No framework, no build step for the app, no server: it runs from a static
host or even straight from `file://`. Gemini is called from the browser with *your own* API key, and only when
the on-device engines can't answer.

---

## Quick start

| I want to… | Do this |
|---|---|
| **Use it** | Open `tracker/index.html` (self-contained, ~2.5 MB). Tap the floating **🧠 button** on any tab (or Track → 🧠 AI Coach, or Command Center → Ask AI Coach). |
| **Host it free** | Push this repo to GitHub → *Settings → Pages → Source: GitHub Actions*. The `deploy-pages` workflow publishes `tracker/`. |
| **Enable Gemini answers** | In the coach: ⚙ → paste a key from <https://aistudio.google.com/apikey> → Save. Stored only in that browser (`localStorage`). |
| **Use it without a key** | Plan, weak chapters, mock trend, quiz, formulas and college chances all work with no key and no network. |

## What the AI Coach does

**On-device, zero API calls**
- *Study tonight* — revise-first list, weak spots, chapters to continue, hours studied
- *Weak chapters* — ranked exactly like the tracker's Weak Spot Radar; each has Quiz / Formulas / Explain buttons
- *Mock trend* — last mocks, change vs the previous three, biggest leaks
- *Quiz* — 978 real JEE Main PYQs (723 MCQ + 255 numerical); starts from your weakest chapter
- *Formulas* — 220 formulas across 20 chapters (KaTeX)
- *Colleges* — JoSAA 2023-24 cutoffs: `AIR 2500 advanced, CSE at IIT?`, `cutoff for CSE at NIT Trichy`

**Gemini (only when needed)** — doubts and explanations. Every call carries a ~500-character summary of your
tracker (days to exam, syllabus %, weak chapters, revision due, mock trend) and goes through `RequestManager`
(per-minute and per-session limits, audit log, abort).

### Easy to reach, easy to use (accessibility)
- **Floating 🧠 button on every tab** opens the coach as a bottom sheet (side panel on desktop) — no hunting through menus; it hides on the AI tab itself. It also works in Efficient Mode. Turn it off in the coach ⚙ settings.
- **Context hint:** the sheet adds a one-tap suggestion for the tab you came from (e.g. *Quick physics quiz* from the Physics tab, *Analyse my mocks* from Battle Log).
- **Voice input 🎤** (Chrome/Android/Safari where the Web Speech API exists; hidden elsewhere) — speak, review the text, then send.
- **Read aloud 🔊** on AI answers (maths is spoken as "formula").
- **Text size** A− / A+ (85 %–140 %), remembered.
- **Screen readers & keyboard:** modal dialog with focus trap, Esc to close, focus returns to where you were; labelled controls; chat is a live log (announced when an answer is ready, not word-by-word); quiz results use text markers ("✓ correct answer / ✗ your answer"), not colour alone; decorative bars/dots hidden from assistive tech.
- **Touch targets ≥ 44 px** (small buttons ≥ 36 px), visible focus rings, `prefers-reduced-motion` respected.

### Data rules
- The coach is **read-only** on tracker data (`jee-*` localStorage keys). It never writes them.
- Weak score, "complete = 90 %", and "revision due = completed ≥ 20 days ago and not retested" copy the tracker's own rules, so the coach and the dashboard never disagree.
- Coach-only keys (survive the tracker's reset): `jee_key`, `jee_model`, `jee_coach_chat`, `jee_qbank_seen|wrong|correct`.

## Repo layout

```
tracker/
  index.html          ← SHIPPABLE. Tracker + all AI code embedded (generated – don't edit by hand)
  index.split.html    ← the tracker + 5 small edits + lazy loader for ai/*.js  (edit this one)
  ai/                 ← the AI source files
    jee-engines.js      Phase 1: score, rank, syllabus, weak-area, SM-2 revision, timer engines
    jee-formulas.js     Phase 2: formula library
    jee-quizbank.js     Phase 2: 978-question bank (GENERATED by quizbank-build/)
    jee-josaa.js        JoSAA 2023-24 cutoff data + engine (6,087 rows)
    jee-core.js         Phase 3: registry, intent detection, local answers, RequestManager, monitor
    jee-tracker-bridge.js   reads the tracker's localStorage → engine-shaped data + Gemini profile
    jee-coach-ui.js     the chat/dashboard UI for the tab
tools/build_single.py   rebuilds tracker/index.html from index.split.html + ai/*.js
quizbank-build/         rebuilds jee-quizbank.js from the Hugging Face dataset
tests/                  Node unit/integration tests + a Playwright browser test
tutor/                  the older standalone AI Tutor app (not yet connected to the engines)
demos/                  per-phase demo pages (load ../tracker/ai/*.js)
.github/workflows/      test + GitHub Pages deploy
```

### The 6 edits made to the original tracker (`index.split.html`)
1. `NAV_CATEGORIES.track` gets `{ id: 'ai-coach', label: '🧠 AI Coach' }`
2. New `<div id="ai-coach" class="tab-content">` before the `prompts` tab
3. `switchTab()` calls `window.AICoachLoader?.open()` for that tab
4. Command Center gets an "Ask AI Coach" shortcut (also reachable in Efficient Mode, where the Track group is hidden)
5. Two `<script>`s at the very end of `<body>`: the **launcher** (floating button + sheet, ~4 KB, also called from `switchTab()` so the button follows the current tab) and the **loader** — **not** inside the main script (the tracker has HTML templates in strings that contain script tags; inserting there breaks the page)

6. `switchTab()` also calls `window.AICoachLauncher?.onTab(tabId)` on every tab change.

The AI code is embedded as inert `type="text/plain"` blocks and only executed the first time the tab opens,
so tracker start-up time is unchanged.

## Develop

```bash
# edit tracker/ai/*.js (or tracker/index.split.html), then:
python tools/build_single.py            # regenerate tracker/index.html

# tests (Node 18+; no dependencies)
node tests/test-josaa-wiring.js   tracker/ai
node tests/test-quiz-integration.js tracker/ai
node tests/test-tracker-bridge.js tracker/ai

# browser tests (Gemini and speech APIs mocked)
pip install playwright && playwright install chromium
python tests/e2e_tracker_browser.py     # 27 checks: tab, local answers, quiz, JoSAA, Gemini request, data untouched
python tests/e2e_accessibility.py       # 37 checks: floating button, sheet, focus/keyboard, voice, read-aloud, text size, a11y audit
# screenshots go to ./test-output/

# rebuild the quiz bank (download the dataset first: huggingface.co/datasets/eQOURSE/jee-main-questions)
python quizbank-build/build.py path/to/snapshot && python quizbank-build/gen.py
python tools/build_single.py
```

Load order when using the JS files directly: `engines → formulas → quizbank → josaa → core → tracker-bridge`, then
`TrackerBridge.install(core)`.

## Known limitations
- **Quiz bank quality:** built from a public dataset: 854 image questions, ~170 with missing options and ~200 with garbled Hindi text were dropped. Physics is thin (169 questions); chapters `hal` and `hyp` are empty; 88 questions have no written solution; some source answer keys may be wrong.
- **Quiz results are not written back** to the tracker's Daily Questions log.
- **Chapter mapping:** a few tracker chapters map onto merged engine chapters (e.g. surface chemistry / states of matter / solid state → `ss`); Practical Physics has no engine chapter.
- **JoSAA:** `trend()` / `findCutoff()` match program names by substring, so dual-degree variants can mix into "Computer Science". Past cutoffs don't guarantee future ones.
- **NTA score→rank table** in `jee-engines.js` is still hand-approximated.
- **Not yet verified:** real Gemini responses/streaming (tests mock the network), KaTeX rendering on a live CDN, offline behaviour with your `sw.js`, GitHub workflows, **real voice input/read-aloud on a phone** (tests use mocks; voice recognition needs an internet connection and microphone permission, and iOS support varies), and a real screen reader (VoiceOver/TalkBack) — the a11y checks are automated only.
- `tutor/` is the older standalone app; it still calls Gemini directly and doesn't use the engines or the tracker data.

## Security
No secrets are stored in this repo. The Gemini key lives only in the browser's `localStorage`; requests go from your browser straight to Google. Don't commit keys.
